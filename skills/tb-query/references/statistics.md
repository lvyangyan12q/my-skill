# 功能工时与缺陷统计口径

## 归属与阶段

对每个功能建立需求、父子任务及缺陷的对应表。优先采用关联关系与分类，其次采用已核实的描述。关键词只用于找候选项，不直接决定纳入。

| 阶段 | 主要核实依据 |
|---|---|
| 方案设计 | 明确的方案、设计工作项及其阶段 / 类型 |
| 开发 | 明确的功能实现任务；前后端分别登记时均保留 |
| 联调 | 明确的联调、集成验证任务 |
| 自测 | 明确的开发自测任务；不自动将测试团队全部测试工时计为自测 |

一个任务跨多个阶段但没有拆分工时时，列入待分配，不从总数均摊。分析结论和系统字段分别标注，保留纳入理由。

## 工时

默认统计实际登记工时，计划工时作为另一列。按以下顺序核实字段：可见工时登记 / 明细、结构化实际工时、已确认口径的汇总字段。任一字段单位或“含子任务”含义不清时，保留原值而不做推断换算。

- 单位已明确为分钟时可除以 60 转小时，保留原始分钟用于校验。
- 一个父任务已汇总其子任务时，父级与子级不能同时纳入总和。
- 未登记、字段为空与明确登记为 0 分开表达。
- 开始到完成或截止的差值是历时，不能作为实际登记工时。
- 多人投入按实际登记累计，不能仅以负责人一个人的排期估算。

每阶段合计 = 经核实属于该功能及阶段、去重且未重复汇总的任务实际工时之和。任何未覆盖任务或缺失工时都使合计成为“已登记部分”，不能表述为完整耗时。

## 缺陷

按稳定 bug ID 去重，默认统计可见的全部状态，另列未完成 / 已完成或实际工作流状态分布。

- 缺陷重开不新增 bug，重开次数单列。
- 修复任务与 bug 是不同对象，前者不另计缺陷。
- 多功能共用缺陷可在各功能列出，但须注明交叉归属；全局总数再次按 ID 去重。
- 只在未完成视图取得数据时，输出“已读取未完成 bug 数”，不能写为总 bug 数。

## 交付结构

汇总表：功能｜方案设计实际小时｜开发实际小时｜联调实际小时｜自测实际小时｜已登记合计｜计划小时｜bug 数｜覆盖情况。

任务明细：功能｜阶段｜任务 ID / 标题 / 链接｜父级 ID｜人员｜状态｜工时原值｜单位｜换算小时｜是否汇总｜纳入理由。

缺陷明细：功能｜bug ID / 标题 / 链接｜状态｜关联需求 / 任务｜归属依据｜交叉归属。

报告同时列出项目、查询时刻、状态 / 时间范围、分页或加载结束证据、缺失字段和未覆盖范围。用户未提供时间区间时，不擅自限制为最近一周或某次快照。
