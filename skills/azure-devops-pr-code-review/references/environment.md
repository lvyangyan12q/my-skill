# 访问失败时使用

正常评审不必读取本文件。不做整套环境盘点，只定位实际失败的一步。

| 实际信号 | AI 先检查 | 向用户说明的缺失项 |
| --- | --- | --- |
| 没有 PR 地址或 ID 无法定位 | 当前对话和已知仓库信息 | 缺少 PR 地址，或缺少所属项目/仓库 |
| 无可用认证客户端，AZDO_PAT 也未配置 | 仅检查已有安全配置是否可用，不扫描无关凭据 | 当前进程缺少 PAT；请在本机配置 AZDO_PAT 或指定已配置客户端 |
| HTTP 401 | 令牌是否提供、认证方式及服务端要求 | 认证被拒绝；请核对 PAT 有效期及认证方式，不断言一定过期 |
| HTTP 403 | 当前操作是读取还是发布、账号权限 | 缺少相应代码读取或评论权限 |
| HTTP 404 | 集合路径、项目、仓库、PR、API 版本及可见性 | 地址或访问权限待确认；不能据此认定资源不存在 |
| 超时、无法解析或连接 | 目标主机、已有代理/VPN和本地沙箱限制 | 指明失败主机及需要确认的网络路径；有沙箱证据时按工具流程申请重试 |
| TLS 校验失败 | 企业 CA、证书及域名 | 缺少可信证书配置或证书异常；不关闭校验 |
| API 版本不支持 | 服务端版本及现有客户端配置 | 需要匹配版本的 API；不能要求升级整个服务器 |
| API 内容取不全且 Git 不可用 | 本地 Git 和现有克隆 | 仅此时提出 Git/仓库访问需求，并列出当前未审查范围 |
| 规则引用无法读取 | 相对路径、固定提交和引用范围 | 指明缺少的规则文件；其他代码继续评审 |

故障输出示例：“读取 PR 返回 401，当前认证未通过。请在本机更新 AZDO_PAT，并确保执行 AI 的进程能读取；不要发送令牌内容。尚未取得代码，不能给出评审结论。”

## 调用要点

复用安全客户端；直接 REST 时从 AZDO_PAT 构造 Basic 认证（编码冒号加 PAT），不输出认证头。Services 地址通常包含组织，Server/TFS 地址还可能包含集合路径，保持 PR 地址中的路径。API 版本按服务端选择。

本 skill 不依赖 Python 或 uv。已配置的 MCP/客户端若需要额外运行时，仅在其启动失败时按该工具要求排查。代码获取、分页及版本固定见 [读取方法](review-inputs.md)。
