# ASD-STE100 在 output-design 中的用法

## 标准与本技能的区别

ASD-STE100 是面向英文技术文档的受控语言标准，包含写作规则和受控词典；词语的批准含义及词性是其重要部分。依据：[官方 FAQ](https://www.asd-ste100.org/STE_faq.html)、[官方标准入口](https://www.asd-ste100.org/)。

本技能默认采用 Karpathy 提到的宽松借鉴方式：用明确、简洁、一致的表达降低理解成本。“约 80%”不代表计分、认证或覆盖了某个确定比例的规则。它也不是中文标准。

## 实际执行

| 原则 | 对输出执行的动作 |
|---|---|
| 用词一致 | 沿用任务术语表；同一概念用同一名称，技术标识保持原样 |
| 含义明确 | 检查主体、动作、对象和已有条件；模糊处反馈内容提供者，不补猜测 |
| 句子可读 | 拆开多动作长句，条件和结果就近；同时发生的动作保留同时关系 |
| 语义不变 | 对照输入检查否定、数量、先后和不确定性；不能将“可能”变成“确定” |
| 与用途匹配 | 操作指引用清楚步骤，解释性文字保持自然连贯；不把所有文档写成维修手册 |

中文按 [中文表达方法](chinese-expression.md) 执行；英文按 [英文表达方法](english-expression.md) 执行。只读取任务所需语言，不因提到标准同时加载所有分支。

## 用户明确要求严格符合标准时

先明确要求的版本与文档范围，再使用对应正式标准及其词典、适用技术术语规则逐项检查。只有短句、简单语法或一个检查工具通过，都不能独立证明全文合规。

正式标准或词典不可访问时，可以交付明确标注的“参考 STE 原则的改写”，但严格合规检查仍为未完成；不自行编制“官方批准词表”，不把通用中文适配称为 STE 认证。保留原有技术含义优先，表达无法兼顾时说明具体问题。

本仓不复制官方完整规则和词典，也不新增逐句门禁。正式版本要求只在用户明确提出时触发。
