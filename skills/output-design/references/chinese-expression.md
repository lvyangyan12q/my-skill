# 中文表达方法

生成或改写中文正文、图注、控件说明时使用。以下是中文适配方法，不是 ASD-STE100 的官方中文标准；内容由当前任务提供。

## 逐段执行

1. 从当前材料找出本段要表达的主张，保留条件、动作、结果、例外、数字、否定和确定程度。原文没有的内容不补齐。
2. 将主张放在读者容易找到的位置，再把已有原因和限制接在附近。固定模板不改章节；自由结构可调整段落顺序。
3. 把模糊指代换成已知对象，把空泛动作换成已有的具体动作。同一对象使用同一名称；专业名词首次出现时，用已有定义解释。
4. 一段一个主题。长句按因果、条件或先后关系拆开，保留连接词；不要把完整说明切成没有关系的短句。
5. 对照原文逐项核对：范围、数量、条件组合、否定、时间先后和语气是否改变。意思仍不明确时标注表达缺口，交当前任务处理。

## 常见问题怎样改

以下均为合成表达示例，不是项目业务规则。

| 问题 | 原文 | 改写及限制 |
|---|---|---|
| 动作名词堆叠 | 系统进行文件格式合法性的校验操作。 | 系统检查文件格式是否合法。 |
| 条件离结果太远 | 系统保留原值，在用户未提供该字段的情况下。 | 用户未提供该字段时，系统保留原值。 |
| 两种输入混淆 | 未提供字段时保留原值；显式传空时清空。 | 两个条件分别列出，不合并为“字段为空时清空”。 |
| 不确定性被删掉 | 请求可能因超时失败，建议重试。 | 请求可能因超时失败。建议重试。不能改成“请求超时，必须重试”。 |
| 缺口被写成结论 | 单元测试通过，集成测试尚未执行。 | 保留两个状态，不能概括成“验证全部通过”。 |
| 指代不清 | A 将记录交给 B，随后它保存记录。 | 原文不能确定保存者；标注“保存者待明确”，不猜是 A 或 B。 |

## 中文中的精确性

- “并且”与“或者”不同；“仅当”与“如果”不同；“未提供”“null”“空字符串”“空集合”不能混用。
- “至少”“至多”“超过”“不小于”的边界不能互换；数字、单位、版本、接口和代码标识原样核对。
- “未观察到”“未执行”“失败”“不适用”各有含义，保留原状态；建议、待批准和已批准分开。
- 术语采用任务既有名称，不为了去重换同义词。删掉没有具体含义的“赋能、闭环、全方位”等修饰时，保留原文实际指向的动作和结果。
- 中文不设英文词数上限。不以删主语、删条件或电报式短句换取简短。

## 什么时候换形式

一段文字仍需读者记住多种对应关系时，改成条件表或图；读者需要比较场景和观察变化时，使用交互页面。选择方法见主 Skill，具体制作见视觉参考。只需短解释时不额外建文件。

交付前：读者能准确说出本段意思，条件和例外无需跨多处拼接；原有信息没有因改写丢失。该检查评价表达，不判定业务要求是否完整。
